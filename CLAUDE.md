# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a two-part project:
1. **Python tracking engine** (`priv/mouse_tracker.py`) — OpenCV-based video analysis tool that tracks mouse locomotion, computing distance, speed, and occupancy heatmaps.
2. **Phoenix web application** — a web UI being built around the Python script, with user auth, experiment management, and storage of tracking results.

## Commands

### Elixir / Phoenix

```bash
mix setup                  # install deps, create+migrate DB, build assets
mix phx.server             # start dev server at http://localhost:4000
mix test                   # run all tests (auto creates/migrates test DB)
mix test test/path/to_test.exs  # run a single test file
mix precommit              # compile (warnings as errors), format, unused deps, test
mix ecto.reset             # drop + recreate + migrate DB
mix ecto.migrate           # run pending migrations
```

### Python

```bash
uv run python priv/mouse_tracker.py -v <video> -c <cage_side_cm> [options]
```

Key options: `-st`/`-et` (start/end seconds), `-th` (threshold, default 80), `-a` (min contour area, default 250), `-roi` (ROI selection), `-sp`/`-sd`/`-hm` (output plot paths).

Python dependencies are managed with `uv` (see `pyproject.toml` and `.python-version`). Install with `uv sync`.

## Architecture

### Data model

The DB hierarchy is:

```
User
├── Experiment (name, description)
│   └── Video (filename, filepath, fps, status, calibration_id?)
│       ├── ROI (x, y, w, h)
│       │   └── RoiTime (seconds, frame_count) → TrackingResult
│       └── TrackingResult (distance_px/cm, speed_mean/median, heatmap_path)
└── Calibration (cage corners, px_per_10cm, threshold, min_area, valid_region)
```

`Calibration` is reusable across videos. `Video.status` tracks processing state (`"pending"`, etc.).

### Elixir contexts

- `MouseTracker.Accounts` — user registration, login, magic-link auth, password management. Generated by `phx.gen.auth`.
- `MouseTrackerWeb.UserAuth` — plug that loads `current_scope` and enforces auth on protected routes.
- `MouseTracker.Repo` — PostgreSQL via Ecto.

### Auth

The app uses **magic-link login** (passwordless email link) as the primary flow, with optional password. Tokens live in `users_tokens` with a `context` field (`"session"`, `"login"`, `"change:email"`). Sudo mode expires 20 minutes after last authentication.

### Frontend

Phoenix LiveView with Tailwind CSS (v4). JS entry point is `assets/js/app.js`. Templates use `.heex` files. `core_components.ex` defines reusable UI components. **Do not use DaisyUI** — write Tailwind components manually.

### HTTP client

Use the `:req` (`Req`) library for all HTTP requests. **Never** use `:httpoison`, `:tesla`, or `:httpc`. `Req` is already included as a dependency.

### Python ↔ Elixir boundary

The Python script is a standalone CLI today. The web app stores calibration parameters and results in Postgres. Future integration will invoke the Python script as a subprocess or port, passing stored calibration/ROI parameters and writing results back.
