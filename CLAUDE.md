# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a two-part project:
1. **Python tracking engine** (`priv/python/`) — OpenCV-based video analysis tool that tracks mouse locomotion, computing distance, speed, and occupancy heatmaps. `priv/mouse_tracker.py` is deprecated; use the module in `priv/python/` instead.
2. **Phoenix web application** — a web UI being built around the Python script, with user auth, experiment management, and storage of tracking results.

## Commands

### Elixir / Phoenix

```bash
mix setup                  # install deps, create+migrate DB, build assets
mix phx.server             # start dev server at http://localhost:4000
mix test                   # run all tests (auto creates/migrates test DB)
mix test test/path/to_test.exs  # run a single test file
mix precommit              # compile (warnings as errors), format, unused deps, test
mix ecto.reset             # drop + recreate + migrate DB
mix ecto.migrate           # run pending migrations
```

### Python

```bash
# Modo interativo (com janelas OpenCV para calibração e seleção de ROI)
uv run python -m priv.python.run -v <video> -c <cage_side_cm> [options]
```

Key options: `-st`/`-et` (start/end seconds), `-th` (threshold, default 80), `-a` (min contour area, default 250), `-roi` (ROI selection), `-sp`/`-sd`/`-hm` (output plot paths).

```bash
# Modo headless (sem janelas, para integração com o Phoenix)
uv run python -m priv.python.run --json '<json>'
```

JSON obrigatório: `video`, `valid_region` (`[x, y, w, h]`). Opcionais: `start_time`, `end_time`, `threshold` (80), `min_area` (250), `px_per_10cm` (1.0), `rois` ([]), `progress_every` (50), `speed_profile`, `speed_distribution`, `heatmap`.

Saída headless: linhas `{"type":"progress","value":42.5}` durante o processamento, seguido de `{"type":"result","distance_cm":...}` ao final.

Python dependencies são gerenciadas com `uv` (veja `pyproject.toml` e `.python-version`). Instale com `uv sync`.

## Architecture

### Data model

The DB hierarchy is:

```
User
├── Experiment (name, description)
│   └── Video (filename, filepath, fps, status, calibration_id?)
│       ├── ROI (x, y, w, h)
│       │   └── RoiTime (seconds, frame_count) → TrackingResult
│       └── TrackingResult (distance_px/cm, speed_mean/median, heatmap_path)
└── Calibration (cage corners, px_per_10cm, threshold, min_area, valid_region)
```

`Calibration` is reusable across videos. `Video.status` tracks processing state (`"pending"`, etc.).

### Elixir contexts

- `MouseTracker.Accounts` — user registration, login, magic-link auth, password management. Generated by `phx.gen.auth`.
- `MouseTrackerWeb.UserAuth` — plug that loads `current_scope` and enforces auth on protected routes.
- `MouseTracker.Repo` — PostgreSQL via Ecto.

### Auth

The app uses **magic-link login** (passwordless email link) as the primary flow, with optional password. Tokens live in `users_tokens` with a `context` field (`"session"`, `"login"`, `"change:email"`). Sudo mode expires 20 minutes after last authentication.

### Frontend

Phoenix LiveView with Tailwind CSS (v4). JS entry point is `assets/js/app.js`. Templates use `.heex` files. `core_components.ex` defines reusable UI components. **Do not use DaisyUI** — write Tailwind components manually.

### HTTP client

Use the `:req` (`Req`) library for all HTTP requests. **Never** use `:httpoison`, `:tesla`, or `:httpc`. `Req` is already included as a dependency.

### Python ↔ Elixir boundary

The Python module (`priv/python/`) exposes a headless CLI mode (`--json`) designed to be invoked as a subprocess by Phoenix. The Elixir side will pass calibration and ROI parameters (stored in Postgres) as a JSON string, and read progress/result lines from stdout. Each stdout line is a valid JSON object — either `{"type":"progress","value":N}` or `{"type":"result",...}`.

The module is split into:
- `run.py` — entry point; dispatches to interactive or headless mode
- `analyzer.py` — core tracking loop (`process/9`)
- `detector.py` — frame diffing and thresholding (pure functions)
- `metrics.py` — distance, speed stats, px↔cm conversion (pure functions)
- `render.py` — interactive OpenCV setup + matplotlib plot generation

The ROI format passed via JSON is a flat list: `[x, y, w, h]` for rectangles or `[x, y, radius]` for circles (Python distinguishes by list length).

### Background job processing (Oban)

`MouseTracker.Workers.VideoProcessingWorker` handles async video processing:
1. Receives `%{"video_id" => id}` as job args
2. Preloads `calibration` and `rois` from the video record
3. Sets `video.status = "processing"`, calls `PythonPort.run/1`
4. On success: inserts `TrackingResult`, sets status `"done"`, broadcasts `{:processing_done, video_id}` on PubSub topic `"video:<id>"`
5. On error: sets status `"error"`, returns `{:error, reason}` so Oban retries (max 3 attempts)

Enqueue via: `MouseTracker.Experiments.enqueue_video_processing(video_id)`
